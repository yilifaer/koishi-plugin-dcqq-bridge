# 测试步骤

在真实的 Koishi 里实测本插件的步骤。下面的「测试频道」「测试群」都是举例，换成你自己的。

## 准备

1. 安装本插件，**只配一个桥**：测试 Discord 频道 ↔ 测试 QQ 群，方向「双向」，@全体 先关。
2. 如果还在用 @myrtus/forward，保持它照常运行，但**确认它没有转发这个测试频道和测试群**，否则每条消息会发两次。
3. 打开 Koishi 的日志页面，测试过程中出现的警告都记下来。

## 步骤

每一步做完，对照「预期」一栏。不符合的，记下现象和当时的日志。

| # | 操作 | 预期 |
|---|---|---|
| 0 | QQ 群里发一句普通文字 | Discord 测试频道里出现这句话，名字和头像是 QQ 发送者的。**这一步同时确认了插件能用 Discord 适配器的地址和机器人授权发消息**；不成功时先看日志，把报错发给开发者 |
| 1 | 用一个**普通群成员**的账号私聊机器人发 `bridge.status` | 被拒绝（没有权限）；用你自己的账号可以看到状态 |
| 2 | 两边各发一句普通文字 | 对面收到，前缀正确，没有重复 |
| 3 | Discord 发 `集合 <t:1790000000:F> 出发 <t:1790000000:t> <t:1790000000:R>` | QQ 上三个时间都换算成设定的时区，文字没有丢 |
| 4 | 在测试频道建一个 webhook，用它发一条带标题、描述、3 个字段、页脚、时间戳和图片的 embed | QQ 上作者、标题、描述、每个字段、页脚都在，图片在文字后面 |
| 5 | Discord 发 `price < 5b and > 3b`，再发一条带两个自定义表情的消息，再发 `**粗体** ### 标题 > 引用` | QQ 上文字完整，表情显示成 `[名字]`，Markdown 标记被去掉 |
| 6 | Discord 上分别 ping 一个角色、@here、@everyone（后两个用有 ping 权限的账号） | @全体 关着：QQ 上只有文字，没有 `@undefined` |
| 7 | 先私聊机器人发 `bridge.status` 记下 @全体 剩余次数（这时是「未知」也没关系）。打开这个桥的 @全体，重复第 6 步的 @everyone 和 @here；再用**没有 ping 权限**的账号发 `@everyone`；最后再看一次 `bridge.status` | 前两条 QQ 上真的 @全体成员；第三条不 @全体；`bridge.status` 显示今天的剩余次数（机器人 / 全群）。**把 @全体 前后两个数字的变化记下来**，用来确认次数是按群计算还是全局计算 |
| 8 | 两边各发图片；QQ 发文件、表情包、合并转发、小程序卡片；Discord 转发一条别的服务器的消息 | 图片两边都能看到；其他的显示成占位文字；转发的消息带 `[转发的消息]`；没有东西静默消失 |
| 9 | 分别在 `discordAsWebhook` 开和关两种情况下，QQ 发 `<@某个用户ID>`、`<@&某个角色ID>`、`@everyone` | 两种情况下 Discord 上都**没有**任何人被 ping |
| 10 | 两边互相回复对方转过来的消息；Discord 上回复一条已经删掉的消息 | QQ 上是真正的回复；Discord 上 webhook 模式是「↪ 回复 … · 链接」，机器人模式是真正的回复；回复已删除消息的那条照样转发 |
| 11 | 发一条 2500 字、带很多括号和 `*` 的消息 | 对面分段收到，没有丢段 |
| 12 | 把 QQ 群名片改成带「Discord」字样，发一条消息 | Discord 上正常显示，名字里的 Discord 被拆开（看起来一样，但中间有一个看不见的字符） |
| 13 | 私聊发 `bridge.pause` → 两边发消息 → `bridge.resume` → 重启 Koishi | 暂停期间不转发；恢复后正常；重启后状态保持 |
| 14 | 在 LLBot 那边重启一次（或断开 WebSocket），然后发 `bridge.status` | 显示「QQ 机器人离线」；在控制台重载 onebot 适配器后恢复正常 |
| 15 | （可选）把 `qqReorderMs` 设成 `1000`，在 QQ 上快速连发：一条回复消息，紧跟一条普通消息 | Discord 上两条的顺序和 QQ 上一致。日志里如果出现关于消息序号的提示，把它发给开发者（用来确认 LLBot 有没有带消息序号） |

## 正式切换

1. 上面的步骤全部通过。
2. **私聊**机器人运行 `bridge.import`，核对报告：生成了几个桥、跳过了哪些、为什么跳过。
3. 把生成的 `bridges:` 粘进本插件的配置，删掉测试桥。
4. 先定好 @全体 的 `reserve`、`cooldownMinutes`、`dailyCap`（参考第 7 步的结果），再在需要的桥上打开 @全体。
5. **在同一次保存里**停用 @myrtus/forward、启用本插件。
6. 观察 24 小时：`bridge.status`、Koishi 日志、LLBot 日志。
7. 出问题就退回：停用本插件，启用旧插件（旧插件的配置和数据都没动过）。
